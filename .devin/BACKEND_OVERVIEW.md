## 🔑 Key Concepts

### Middleware (in `src/middleware/`)

**auth.middleware.ts**
- `authenticateToken`: Verifies JWT from `Authorization: Bearer <token>` header, attaches user to request
- `optionalAuth`: Allows unauthenticated requests (user is optional)
- `requireRole(roleId)`: Enforces role-based access control

**validate.middleware.ts**
- `validateBody(schema)`: Validates request body against Zod schema
- `validateParams(schema)`: Validates URL parameters
- `validateQuery(schema)`: Validates query parameters
- `validateRequest(schema)`: Validates body, params, and query together

**error.middleware.ts**
- `errorMiddleware`: Global error handler (catches all errors)
- `asyncHandler(fn)`: Wraps async route handlers to catch errors

### Authentication & Authorization
- **JWT-based**: `authenticateToken` middleware verifies tokens from `Authorization: Bearer <token>` header
- **Optional Auth**: `optionalAuth` middleware allows unauthenticated requests
- **Role-based Access**: `requireRole(roleId)` middleware enforces role permissions
- **Roles**: `guest` (1), `user` (2), `hotel_owner` (3), `admin` (4)

### Request/Response Pattern
- **AuthenticatedRequest**: Extended Express Request with `user` and `userId` properties
- **ApiResponseHandler**: Centralized response formatting
  - `.success(res, data, message, statusCode)`
  - `.error(res, message, statusCode)`
  - `.paginated(res, data, pagination, message)`
  - `.unauthorized(res, message)`
  - `.forbidden(res, message)`

### Error Handling
- **HttpError**: Custom error class with `statusCode` and `message`
- **Global Error Middleware**: Catches all errors, returns standardized format
- **Validation Errors**: express-validator + Zod schemas

### Database Relations
```
User (1) ──→ (M) Hotel (via HotelOwner junction)
User (1) ──→ (M) Booking
Hotel (1) ──→ (M) Room
Hotel (1) ──→ (M) RoomType
Room (M) ←──→ (M) Booking (via BookingRoom junction)
User (M) ←──→ (M) Role (via HotelOwner)
Role (M) ←──→ (M) Permission (via RolePermission)
```

## 🛣️ API Routes

All routes are defined in `src/features/<feature>/<feature>.routes.ts` and mounted in `src/app.ts`.

### Route Structure
```typescript
// src/features/auth/auth.routes.ts
const router = Router();
const authController = new AuthController();

router.post('/register', validateBody(RegisterSchema), authController.register);
router.post('/login', validateBody(LoginSchema), authController.login);
router.post('/refresh', authController.refresh);
router.post('/logout', authenticateToken, authController.logout);
router.get('/profile', authenticateToken, authController.getProfile);

export default router;
```

### Route Mounting (in app.ts)
```typescript
app.use('/api/auth', authRoutes);
app.use('/api/hotels', hotelRoutes);
app.use('/api/hotels/:hotelId/rooms', roomRoutes);
// ... etc
```

### Available Endpoints

| Route | Feature | Methods | Description |
|-------|---------|---------|-------------|
| `/api/auth` | auth | POST | Register, login, refresh token, logout |
| `/api/hotels` | hotel | GET, POST, PUT, DELETE | CRUD hotels, list with search & pagination |
| `/api/hotels/:hotelId/rooms` | room | GET, POST, PUT, DELETE | CRUD rooms per hotel |
| `/api/hotels/:hotelId/room-types` | roomType | GET, POST, PUT, DELETE | CRUD room types per hotel |
| `/api/hotels/:hotelId/availability` | availability | GET | Check room availability by date range |
| `/api/bookings` | booking | GET, POST, PUT, DELETE | CRUD bookings, multi-room support |
| `/api/hotel-requests` | hotel-request | GET, POST, PUT, DELETE | Submit/approve hotel requests |
| `/api/media` | media | GET, POST, PUT, DELETE | Upload/delete images via ImageKit |
| `/api/rbac` | rbac | GET, POST, PUT, DELETE | Manage roles & permissions |

## 🔧 Common Patterns

### Feature Module Structure
Each feature (e.g., `hotel/`) follows this pattern:

```typescript
// controller.ts - Request handlers
export class HotelController {
  static async create(req: AuthenticatedRequest, res: Response) { }
  static async getById(req: AuthenticatedRequest, res: Response) { }
  static async update(req: AuthenticatedRequest, res: Response) { }
  static async delete(req: AuthenticatedRequest, res: Response) { }
}

// service.ts - Business logic
export class HotelService {
  static async createHotel(data: CreateHotelDTO) { }
  static async getHotelById(id: string) { }
}

// repository.ts - Database access
export class HotelRepository extends BaseRepository<Hotel> {
  constructor() { super(Hotel); }
  async findByOwnerId(userId: number) { }
}

// routes.ts - Route definitions
const router = express.Router();
router.post('/', authenticateToken, validate(createSchema), HotelController.create);
router.get('/:id', HotelController.getById);
export const hotelRoutes = router;

// index.ts - Export routes
export { hotelRoutes };
```

### Middleware Usage in Routes
```typescript
import { Router } from 'express';
import { authenticateToken, requireRole } from '@/middleware/auth.middleware';
import { validateBody } from '@/middleware/validate.middleware';
import { createHotelSchema } from '@hotelsonweb/shared';

const router = Router();

// Public route
router.get('/', HotelController.getHotels);

// Authenticated route
router.post('/', authenticateToken, validateBody(createHotelSchema), HotelController.create);

// Role-based route
router.delete('/:id', authenticateToken, requireRole(4), HotelController.delete); // Admin only

export default router;
```

### Validation Pattern
```typescript
// Zod schema (from shared package)
const createHotelSchema = z.object({
  name: z.string().min(2),
  city: z.string(),
  country: z.string(),
});

// In route - validate request body
router.post('/', validateBody(createHotelSchema), HotelController.create);

// In controller - access validated data
export class HotelController {
  create = asyncHandler(async (req: Request, res: Response) => {
    const { name, city, country } = req.body; // Already validated
    // ... create hotel
  });
}
```

### Pagination Pattern
```typescript
const { page = 1, limit = 10 } = req.query;
const { data, pagination } = await HotelRepository.findAll({
  pagination: { page: Number(page), limit: Number(limit) }
});
return ApiResponseHandler.paginated(res, data, pagination);
```

## ⚠️ Common Issues & Solutions

### TypeScript Compilation Errors
- **Missing imports**: Check path aliases in `tsconfig.json` (baseUrl: ".", paths: "@/*": "src/*")
- **Module not found**: Ensure file exists and import path is correct
- **Type errors**: Check model definitions and middleware types

### Database Issues
- **Connection failed**: Verify `.env` credentials and PostgreSQL is running
- **Migration errors**: Check migration files in `migrations/` folder
- **Sync errors**: Ensure models are properly defined with decorators

### JWT Errors
- **Token expired**: Client should refresh token
- **Invalid token**: Check JWT_SECRET matches between signing and verification
- **No token**: Ensure `Authorization: Bearer <token>` header is present

## 🎯 When Adding New Features

1. **Create Model** in `src/models/` with TypeScript + decorators
2. **Define Associations** in `src/models/index.ts`
3. **Create Feature Module** in `src/features/<feature>/`:
   - `<feature>.controller.ts` - Request handlers
   - `<feature>.service.ts` - Business logic
   - `<feature>.repository.ts` - Database queries
   - `<feature>.routes.ts` - Route definitions
   - `index.ts` - Export routes
4. **Add Validation** using Zod schemas
5. **Mount Routes** in `src/app.ts` under `app.initialize()`
6. **Create Migration** if needed: `npx sequelize-cli migration:generate --name <name>`
